# Rebase / merge log — 2026-05-24

## Strategy choice: merge, not rebase

The brief asked for a rebase of `upstream/feature/terrain-3d` onto `upstream/main`.
After the first conflict surfaced on commit 3 of 44 (`# terrain shaders`,
`src/mbgl/shaders/shader_source.cpp`), it was clear the per-commit conflict
volume would eat the time budget. Instead, did a single `git merge upstream/main`
into `letsgothru/terrain-3d` and resolved 5 conflicts in one pass.

This costs a merge commit instead of linear history. For a private fork
we don't intend to PR upstream, that's the right tradeoff. If we later
want to send work back upstream, we can re-do this as a proper rebase
(the conflicts will then be cherry-pickable from this merge commit's
resolutions).

## Conflicts (5 files)

### 1. `include/mbgl/renderer/layer_group.hpp`

- **PR side** added `bool renderToTerrain;` field + `shouldRenderToTerrain()` getter.
- **Main side** added `gfx::ContextObserver* observer;` + `setObserver(...)` helper.

These are non-overlapping additions to the same class. **Resolution: keep both.**

### 2. `src/mbgl/gl/context.cpp` (2 hunks)

`createTileLayerGroup` and `createLayerGroup`:
- **PR side** added `bool renderToTerrain` parameter, threads it into the
  `*LayerGroupGL` constructor.
- **Main side** kept the old signature but now calls
  `tileLayerGroup->setObserver(observer)` after construction.

**Resolution: keep PR's new signature + add main's setObserver call.**
PR's threaded `renderToTerrain` is the load-bearing terrain change; main's
observer wiring is independent infra.

### 3. `src/mbgl/mtl/context.cpp`

Same pattern as gl/context.cpp. **Same resolution.**

### 4. `src/mbgl/mtl/drawable.cpp` (2 hunks)

`bindTextures` and `uploadTextures`:
- **PR side** changed signatures to `noexcept`, added a `const bool isTerrain
  = (getName() == "terrain-tile");` debug branch with `Log::Info` calls
  inside the loop.
- **Main side** kept the same signatures without `noexcept`, no debug.

**Initial resolution** (kept PR's `noexcept`) caused a compile error —
`include/mbgl/mtl/drawable.hpp` declares both methods *without* `noexcept`
on upstream/main, and the PR did not update the header.

**Final resolution: dropped `noexcept` from the .cpp** so signature matches
the header. Kept the terrain debug logging branch. To re-add `noexcept`
we'd need to also update the header — a Phase 2 cleanup.

### 5. `platform/darwin/src/MLNMapSnapshotter.mm`

- **PR side** had a verbose `std::optional<std::string>(std::string(...))` ctor.
- **Main side** uses the C++17 CTAD short form `std::optional(std::string(...))`.

**Resolution: keep main's short form.** Purely cosmetic, post-C++17.

## Post-merge build fix — `src/mbgl/shaders/mtl/terrain.cpp`

Upstream/main changed the `AttributeInfo` constructor signature from
3 args `(index, dataType, id)` to 4 args
`(index, dataType, bufferIndex, id)`. The PR's terrain.cpp was still
on the old signature. Fixed by adapting to the new shape — the
`bufferIndex` is what used to be passed as the first argument
(`terrainUBOCount + N`); the `index` is the attribute slot (0, 1).
Confirmed pattern against `src/mbgl/shaders/mtl/raster.cpp` in main.

This is a real "PR fell behind main" issue. There are probably more
of these — every shader the PR added (terrain, plus any future
3D-buildings shaders) and every renderer hook it patched needs to be
re-validated against current main interfaces. See PROGRESS.md
"Known gaps".

## Submodule housekeeping

The original `git clone --recurse-submodules` got interrupted while cloning
`platform/windows/vendor/vcpkg` (1+ GB, windows-only). Cleaned up:

```
rm -rf platform/windows/vendor/vcpkg .git/modules/platform/windows
git config --remove-section submodule.platform/windows/vendor/vcpkg
```

We do not need vcpkg for our iOS/macOS work. If a future agent needs to
build for Windows, re-init that submodule explicitly:

```
git submodule update --init platform/windows/vendor/vcpkg
```

All other submodules initialised cleanly via `git submodule update --init --recursive`.
